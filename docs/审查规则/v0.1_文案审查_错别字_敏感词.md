## 1. 适用范围

| 项 | 说明 |
|---|------|
| 适用 | 页面文案、落地页、推送通知、邮件正文、按钮文案、错误提示、表单 placeholder |
| 不适用 | 代码注释、log 文本、API 错误码(技术文本)、英文 i18n(本规则 v0.1 仅中文) |
| 优先级 | **P0** —— 模块 1 审查器最底层的"硬错"层,先于风格/品牌/语气 |

## 2. 核心原则

> **错别字先于风格** —— 永远先扫硬错(错字/漏字/多字),再评软调(语气/品牌)。
> 硬错率不归零,软调评价无意义。

## 3. 错别字规则(可机检)

### R-TYPO-01 · 同音/形近字自动检测

- **规则**: 触发形近/同音字表(高优先级 Top 50,见附录 A),命中即标记 `[typo]`
- **示例**:
  - ❌ "请在**未**小时内确认" → 应为"请在**48**小时内确认"(数字误用不在本规则,属规则 04)
  - ❌ "账号**登陆**" → 应为"账号**登录**"
  - ❌ "**辨**论区" → 应为"**辩**论区"
- **机检方式**: LLM 二次校验 + 同音字字典(hanlp / 结巴)
- **阈值**: 1 次命中即报,不设容差

### R-TYPO-02 · 多字/漏字/重复字

- **规则**: 同一汉字连续出现 ≥ 2 次,标记 `[dup]`,除非为叠词("看看""慢慢""干干净净")
- **示例**:
  - ❌ "请请确认" → 应为"请确认"
  - ❌ "的的的士" → 应为"的士"
  - ✅ "慢慢来" → 合法叠词
- **机检方式**: regex `(.)\1{1,}` + 叠词白名单
- **阈值**: 命中即报,白名单豁免

### R-TYPO-03 · 标点符号错误(中文/英文混用)

- **规则**: 中文文本禁止出现纯英文标点(`.`, `,`, `:`, `;`, `?`, `!`),反之亦然
- **示例**:
  - ❌ "请确认,你已注册成功."(中文文本出现英文逗号+句号)
  - ✅ "请确认,你已注册成功。"
- **机检方式**: 根据文本主语种切换标点字典
- **阈值**: 每出现 1 个混用标点,扣 1 分(单条文案上限 5 分)

### R-TYPO-04 · 数字/量词一致性

- **规则**: 数字+量词必须匹配中文习惯(如"一只"≠"一条"用于鸟类,但可用于"一条新闻")
- **示例**:
  - ❌ "一**只**新闻" → 应为"一**条**新闻"
  - ❌ "一**条**小狗" → 应为"一**只**小狗"
- **机检方式**: LLM 常识校验 + 量词映射表
- **阈值**: 命中即报

### R-TYPO-05 · 全角/半角混用

- **规则**: 数字、英文字母、符号在半角/全角之间必须一致
- **示例**:
  - ❌ "注册１次" → 应为"注册1次"
  - ❌ "1次免费" → 应为"1 次免费"(中文+数字间应留空格)
- **机检方式**: regex 检测 `[\uFF10-\uFF19]` + 字符类型边界
- **阈值**: 每出现 1 处混用,扣 1 分

## 4. 敏感词规则(分级)

### 4.1 硬敏感(HARD)—— 0 容忍

- **触发条件**: 命中法律/政治/民族/宗教/色情/暴恐 6 大类硬敏感词表
- **处理**: **直接阻断** —— 整条文案拒绝入库/发布,触发审批流(对接飞书审批 API)
- **词表来源**: 网信办定期发布敏感词表 + 公司法务补充清单
- **示例**:
  - ❌ 任何含政治敏感词的文案
  - ❌ 任何含民族歧视语义的文案

### 4.2 软敏感(SOFT)—— 按"次数+位置"扣分

- **触发条件**: 命中夸大/承诺/绝对化/医疗/金融/未成年人保护 6 类软敏感词表
- **处理**: **不阻断,但扣分** —— 累计扣分 ≥ 5 时,标记 `[soft-warn]`,需文案确认
- **扣分公式**:
  ```
  score = Σ (词频 × 位置权重)
  位置权重: 标题 3.0 / 首段 2.0 / 中段 1.0 / 末尾 0.5
  ```
- **示例**:
  - ❌ "**最佳**体验,行业**第一**"(标题处"最佳"3.0 + "第一"3.0 = 6.0 → warn)
  - ✅ "**很好**的体验"("很好"不在软敏感表 → 0 分)
  - ⚠️ "我们**承诺**30 天退款"("承诺"在软敏感表,中段位置 1.0 × 1 = 1.0 → 暂不 warn)

### 4.3 上下文豁免

- 软敏感词若出现在**否定句**中(如"不要承诺做不到的事"),自动豁免
- 软敏感词若被**引号/书名号/反引号**包裹(如《最佳实践指南》),视为引用而非断言,自动豁免

## 5. LLM Prompt 种子(给文案审查器)

```markdown
# 角色
你是 DetailAdvisor 文案审查员,负责对用户提交的文案做"错别字 + 敏感词"硬错层审查。

# 输入
- 待审查文案: <TEXT>
- 适用场景: <SCENE>(页面/落地页/推送/邮件/按钮/错误提示)

# 审查流程
1. 先跑规则 R-TYPO-01 ~ 05(可机检),输出命中项
2. 再查硬敏感词表(网信办 + 法务清单),命中即阻断
3. 再查软敏感词表,按"次数+位置"计算扣分
4. 给出最终评级: PASS / SOFT_WARN / HARD_BLOCK

# 输出格式(JSON)
{
  "verdict": "PASS" | "SOFT_WARN" | "HARD_BLOCK",
  "typo_hits": [
    {"rule": "R-TYPO-XX", "text": "<原文片段>", "position": <字符偏移>, "suggestion": "<修正>"}
  ],
  "soft_hits": [
    {"word": "<软敏感词>", "count": <次数>, "position_weights": [...], "score": <分数>}
  ],
  "hard_hits": [
    {"word": "<硬敏感词>", "count": <次数>, "category": "<6大类之一>"}
  ],
  "score_deduction": <总扣分>,
  "summary": "<一句话总结>"
}
```

## 7. 测试用例

### TC-01 · 错别字单规则命中

- **输入**: "账号登陆成功"
- **期望**: `verdict: PASS`,`typo_hits: [{rule: "R-TYPO-01", suggestion: "登录"}]`

### TC-02 · 硬敏感词阻断

- **输入**: 任意含网信办敏感词表中的词
- **期望**: `verdict: HARD_BLOCK`,`hard_hits: [{category: "政治"}]`,整条文案标记拒绝

### TC-03 · 软敏感词累计超阈值

- **输入**: "最佳体验,行业第一,绝对领先"
- **期望**: `verdict: SOFT_WARN`,`score_deduction: ≥ 5`,`soft_hits` 含 3 个词

### TC-04 · 上下文豁免

- **输入**: "不要承诺做不到的事"
- **期望**: `verdict: PASS`,`soft_hits` 为空(否定句豁免)
